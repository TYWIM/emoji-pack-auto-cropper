## 一、代码与工程层面

### P1 优先修复

1. **✅ 不是 git 仓库** — 已 `git init` 并提交基线（88108f5） — `git status` 报 `not a git repository`。无版本控制，无法回滚、无法追踪改动。应 `git init` 并做首次提交。
2. **✅ 半透明像素转 GIF 硬切** — 已实现 `_gif_friendly` 预乘（实验验证：白边 255 → 平滑渐变），新增回归测试 `test_gif_export_has_no_white_halo_edge` — 实测：带抗锯齿边缘的图，原始 1244 个半透明像素，转 GIF 后为 0 个。Pillow 的 GIF 保存会把半透明像素量化为全透明或不透明，导致圆角/描边/抗锯齿边缘出现锯齿和白边。建议对 GIF 输出做边缘预处理（半透明像素向主体色 premultiply 后再量化）。
3. **✅ 上传先读后校验** — `_read_upload` 流式读取，超 25MB 立即 422，测试 `test_analyze_rejects_oversized_file` — `analyze` 中 `await file.read()` 把整个文件读进内存后才检查 25MB 限制。应流式读取、边读边限。
4. **✅ 前端依赖 CDN 图标** — lucide 已下载至 `app/static/vendor/lucide.min.js`，离线可用 — `index.html` 引用 `https://unpkg.com/lucide@0.468.0/...`。离线时图标全部静默消失（`window.lucide` 不存在时 `createIcons` 静默跳过），国内网络 unpkg 常不可达。应下载到 `static/` 或内联 SVG。

## 二、UI / 用户体验层面（用户旅程视角）

> 依据 `app/static/` 源码与 Playwright 页面快照（`.playwright-cli/page-*.yml`）审查。

### A. 数据丢失类（最严重）

1. **✅ "重新识别"与"换一张"会静默清空所有命名和启停设置** — 已加确认弹窗（Playwright 验证：取消保留、接受重置）。这是最大的交互陷阱，已修复。
2. **✅ 手动修正模式删除裁剪框无确认、无撤销** — 已加撤销/重做（按钮 + Ctrl+Z/Ctrl+Y，50 步历史；Playwright 验证增删恢复） — 误删不可恢复；移动/缩放误操作同样无法回退。编辑模式没有"撤销/重做"。
3. **⬜ 会话过期无预警** — 2 小时 TTL 到期或服务重启后，用户填写大量名称后点导出才报"处理记录已过期"，工作全部丢失。应在操作中提前提示剩余时间或保留名称到本地草稿。

### B. 命名效率类

4. **✅ 无批量命名** — 已加批量命名条（应用到全部启用项），并支持 Enter 流转到下一张 — 默认全部叫"表情"，40 张需逐张手动改名（快照中 6 张全是"表情"）。建议支持复制上一行、批量设置、或"未命名"自动编号提示。
5. **⬜ 名称校验无原因提示** — 输入非汉字只显示红框，没有 toast 说明"只能 1–4 个汉字"，用户可能困惑。
6. **✅ 无 Enter/Tab 快捷流转** — 名称输入 Enter 跳下一张 — 输入框连续填写只能靠 Tab，无 Enter 跳到下一张。

### C. 识别确认类

7. **✅ 缩略图 62px 太小** — 点击缩略图弹出 300px 放大预览（lightbox，Esc/背景/按钮关闭） — 无法判断识别框是否准确、表情是否完整。建议点击放大预览（lightbox）或支持更大的缩略图。
8. **⬜ 列表行点击与 checkbox 意图歧义** — 点整行是"选中画布框"，点小 checkbox 才是"启停"（18px 热区小、易误点）。新手会以为点行切换启停。建议行点击切换启停、或用更大的开关控件。
9. **⬜ 无"识别异常"引导** — 自动识别数量明显异常（如只有 1 个框）时没有提示"试试规则网格"。
10. **⬜ 无排序调整** — 检测顺序即导出顺序，无法拖拽重排（与 P3-9 重复，可合并）。

### D. 手动修正体验类

11. **⬜ 缩放把手仅右下角 12px 方块** — 低缩放下几乎不可见；无四角把手、无键盘 nudge（canvas 有 tabindex 但无 keydown 处理）。
12. **⬜ 新增框定位不友好** — 默认放画布正中央，可能遮挡已有内容；画布滚动到别处时新框不可见。
13. **⬜ 编辑模式无"重置该框为自动识别结果"**。

### E. 上传与引导类

14. **⬜ 拖拽落点只在 dropZone** — 文件拖到页面其他区域无高亮落点提示，用户会困惑为何拖不进去。
15. **⬜ 首次使用无示例引导** — 没有"试试示例拼图"入口或拼图格式说明图。
16. **⬜ 无多文件提示** — 一次只能处理一张，但页面未说明；拖入多文件时静默取第一个。

### F. 错误与状态反馈类

17. **⬜ toast 3.2 秒自动消失** — 错误信息（如会话过期）一闪而过；关键错误应持久显示或可关闭。
18. **⬜ detectMeta 信息量低** — "自动识别 · 1:1 裁切"不显示检测耗时/主体数，可改进。

### G. 技术性 UI 问题

19. **⬜ 大图 canvas 全分辨率绘制** — 4000 万像素 RGBA 约 160MB，Safari canvas 面积限制（约 16.7M 像素）会直接空白。应按显示区域降采样绘制。
20. **⬜ fitCanvas 的 25% 下限** — 超宽原图在窄屏上"完整显示"可能仍显示不全（zoom 被 clamp 到 0.25）。
21. **⬜ 对比度轻微不达标** — `--muted: #777873` 灰字 11–13px 在浅底上约 4.2:1，略低于 WCAG AA 4.5:1。

### H. 保持的优点

- checkbox 有 aria-label、toast 有 role=status、canvas 有 aria-label，无障碍基础不错。
- 名称即时校验红框反馈、导出按钮状态切换（"正在打包"）、编辑模式提示文字（"拖动框体移动…"）都做得到位。
- 移动端两栏折叠为单栏、导出按钮全宽，窄屏适配已考虑。
